## 1. 意图

对整个仓库做一次体检，把已确认的问题和值得做的改进整理成一份分级路线图。你从中挑选要落地的部分，每一批都能单独发布。

你已做的两个决定：

1. **范围**：全面体检，覆盖缺陷与隐私、AI 体验、性能、工程化四个维度，按 P0 / P1 / P2 分级。
2. **改动幅度**：保持零构建（不打包、原生脚本直接加载），渐进整理。允许拆分大文件、合并重复逻辑、逐步用 `fetch` 替换 jQuery，开发侧可加 lint 与 CI。

## 2. 目标、非目标、反目标

**目标**

- 修掉会让笔记以错误可见范围保存的问题，以及其他已确认的缺陷。
- 让 AI 功能在长文上可用，并且可以取消。
- 去掉每次点击都拉取全部笔记这类明显的浪费。
- 给仓库补上自动检查，让以后的改动更不容易出回归。

**非目标**

- 不引入打包器、TypeScript 或前端框架。
- 不重做界面，不新增功能入口。
- 不改变 Memos 新旧接口的兼容范围（26.10+ 的 `api/` 与旧版 `api/v1/`）。
- 不更换内置模型清单。

**反目标**（即使技术上做成了也算失败）

- 任何一步导致草稿丢失、重复创建笔记，或把笔记存成比用户预期更公开的范围。
- 一次性大改导致无法逐批发布、无法回退。
- 为了"整洁"而重写目前工作良好的部分（草稿锁与三方合并、保存幂等重试、剪藏输入校验）。

## 3. 约束

- Chrome Manifest V3，页面与 Service Worker 均为原生脚本，靠 `<script>` 顺序和 `importScripts` 组织。
- 三种界面语言（简体中文、英语、日语）必须同步。
- `npm test` 现有 64 项测试必须保持通过；有意改变行为时，同一提交里更新对应测试。
- 发布包只含运行时白名单文件（`scripts/package-extension.ps1` 已保证）。
- 已同步到用户浏览器的旧设置、旧草稿、旧预设必须继续可读。

## 7. 分批路线

每一批是一个独立的小项目，落地前单独写实施计划。建议按编号顺序做，第 0 批最先。

### 第 0 批（P0）：隐私与正确性

**V1 + V2　标签可见性规则**

- 现状：`resolveVisibility` 用 `/(#[^\s#]+)/` 取正文里第一个匹配，再与设置里的隐藏标签、公开标签做全等比较。实测 `见 https://a.com/p#top 然后 #私密` 取到的是 `#top`，`第 #1 条 #私密` 取到 `#1`，代码块里的 `#include` 也会被取到。结果是隐藏标签不生效，笔记按默认范围保存。另外设置页标签写的是"标签名"，用户若填 `私密` 而不是 `#私密`，规则永远不匹配。
- 做法：
  1. 新增一个纯函数，提取正文中的全部标签：跳过围栏代码块、行内代码、网址和 Markdown 链接目标。
  2. 规则改为"任意位置出现即生效"。隐藏标签与公开标签同时出现时，**隐藏优先**。（我的默认选择，可改）
  3. 比较前两边都去掉开头的 `#`，设置页保存时也做同样规整。
  4. 保存成功后，用服务器返回的 `memo.tags` 复核一次：若含隐藏标签而实际范围不是私有，提示用户并提供"改为仅自己可见"的一键操作。（我的默认选择，可改；这是第二道保险，可以不做）
- 涉及文件：`js/oper.js`、`js/workspace.js`（生效提示）、`js/settings.js`、三个语言文件。第 4 点还需要在 `js/memos-api.js` 新增"修改可见范围"的调用，目前那里只有归档这一个修改接口（`js/memos-api.js:179-185`）。
- 验证：新增单元测试覆盖上面三个反例、代码块、同时出现两种标签、带与不带 `#` 的设置值；浏览器验收脚本加一条"第二个标签是隐藏标签时保存为私有"。

**B1　归档后列表状态**

- 现状：归档成功后 `clearMemoList()` 清空整个列表，而 `Workspace` 内部的 `results` 没更新，"加载更多"按钮也还在，点了会把已归档的那条重新渲染出来。归档是单击即执行，没有确认也没有撤销。
- 做法：`Workspace` 提供按资源名移除一条结果的方法，只删这一条并保留分页状态；随机回顾的单条结果直接移除。提示条改为"已归档 · 撤销"，撤销即把状态改回正常。（撤销是我的默认选择，可改）
- 涉及文件：`js/oper.js`、`js/workspace.js`、`js/memos-api.js`（恢复接口）、语言文件。
- 验证：单元测试——两页结果中归档第一页某条后，列表只少一条，再加载更多不出现该条；撤销后服务端状态恢复。

**A1　AI 输出截断**

- 现状：输出上限固定 2000 token（New API 不传上限）。只要服务商报告截断，就丢弃全部结果并提示"请缩短原文"。"整理"任务的输出与原文等长，剪藏一篇长文几乎必然失败。对带推理的模型，推理 token 通常也计入这个上限（OpenAI Responses 和 Gemini 都是如此，落地时请对照当前文档确认），可见输出会更少。
- 做法：
  1. 上限改为可配置，默认 8192，设置页"AI 模型"里加一个数字输入。全局一个值，存在同步存储的新键里，不放进各提供商配置。（我的默认选择）
  2. New API 保持现状，默认不传上限，只有用户填了才传：网关后面的模型上限各不相同。（我的默认选择）
  3. 个别模型的上限低于 8192 时服务商会返回 400。这种情况靠 A5 把服务商的原因显示出来，所以 A5 的错误信息部分建议和 A1 一起做。
  4. 截断时不再丢弃：把已得到的文本放进审阅面板，并显示"结果被截断"的警告；审阅对象上记一个 `truncated` 标记。
- 涉及文件：`js/llm-config.js`、`js/ai-optimize.js`、`js/ai-workflow.js`、`js/ai-review.js`、`options.html`、语言文件。
- 验证：`tests/current-release.test.cjs` 里"截断即报错"的断言改为"截断结果进入审阅并带警告"；新增测试确认配置值写进四种请求体。

**B2　日语相对时间**

- 现状：只带了 dayjs 的 zh-cn 语言包。实测切到日语后 `dayjs.locale('ja')` 不生效，沿用上一次的语言，显示 `3 小时前` 或 `3 hours ago`。
- 做法：用浏览器内置的 `Intl.RelativeTimeFormat` 写一个十几行的小函数替换 dayjs，删掉 `js/dayjs.min.js`、`js/zh-cn.js`、`js/relativeTime.js` 三个文件和 `popup.html` 里对应的三行。实测内置实现给出 `3 時間前` / `3小时前`。
- 备选：只补一个 dayjs 日语包。改动更小，但继续保留三个手工拷贝的文件。
- 涉及文件：`js/oper.js`、`js/i18n.js`、`popup.html`、`tests/memos-compat.test.cjs`（桩里有 `dayjs`）。
- 验证：单元测试对三种语言各断言一次输出。

### 第 1 批（P1）：AI 体验

**A2　提示词整理**

- 现状：`AIWorkflow.buildPrompt` 对"整理"任务在英文指令后追加 `LLM_CONFIG.systemPrompt` 全文（实测 7360 字节、4005 个字符，数千 token）。其中代码块示例因多层转义留下了字面反斜杠和不成对的反引号，`</ tag>` 多一个空格，"每条内容尽量打标签"与"1–3 个标签为宜"并存。
- 做法：重写为约 1 KB 的精简版，只保留"必须原样保留的内容"清单和待办用复选框的规则，与 `js/ai-workflow.js` 里其他四个任务的指令放在同一处。用户正文用明确的分隔标记包起来。
- 涉及文件：`js/llm-config.js`、`js/ai-workflow.js`、`tests/ai-workflow.test.cjs`。
- 验证：现有提示词结构测试继续通过；新增断言限制"整理"系统提示词的长度上限。效果需要你用几篇真实笔记手动对比，自动测试不调用真实模型。

**A3　输出语言**

- 现状：每个任务都附带"即使原文是其他语言，也必须翻译成界面语言"。中文界面下"整理"一篇英文文章会得到整篇译文，这与"整理"任务"不丢信息、不压缩"的定位不一致。
- 补充发现：自定义任务也被附上这条强制翻译指令。中文界面下自定义提示词写"翻译成英文"，系统提示词里同时有"必须用简体中文输出"，两条互相矛盾。
- 考虑过的做法：
  1. 三选一设置，默认"自动"。**已选定（2026-11-24）**：默认行为合理，依赖现有行为的人可以切回去。
  2. 不加设置，按任务写死规则。改动最小，但现在靠"整理"顺便翻译外文的人没有退路。
  3. 二选一设置（跟随界面语言 / 跟随原文），默认保持现状。不改变现有行为，但默认下问题依旧，而且两个值表达不了"整理跟随原文、其余跟随界面语言"。
- 做法：设置页"AI 模型"里加一个下拉框"AI 输出语言"，全局一个值，存在同步存储的新键 `llmOutputLanguage` 里（与 A1 的输出上限同样处理），取值 `auto` / `ui` / `source`，没有值或值无法识别时按 `auto`。各取值下每个任务附带的语言指令：

  | 取值 | 整理 | 摘要、要点、问答 | 自定义 |
  | --- | --- | --- | --- |
  | `auto` 自动（默认） | 原文语言 | 界面语言 | 不附带 |
  | `ui` 始终界面语言 | 界面语言 | 界面语言 | 界面语言（弱） |
  | `source` 始终跟随原文 | 原文语言 | 原文语言 | 原文语言（弱） |

  - "界面语言"指令沿用现有三种语言的文字。
  - "原文语言"指令是新写的一段：用笔记本身的语言输出，不翻译；笔记混用多种语言时，每一段保持各自的语言；新加的标签用笔记的主要语言。
  - "弱"表示指令以"除非上面的任务说明指定了输出语言"开头，自定义提示词写明语言时以提示词为准。（我的选择，可改）
  - `auto` 下自定义任务不附带语言指令，由提示词和模型自行决定：改写类提示词（如"修正语法"）应保持原文，提取类提示词各有需要，替用户定哪一种都会错一半。（我的选择，可改）
- 这会改变现有行为：升级后"整理"外文笔记不再得到译文。在更新日志里写明，并说明切到"始终界面语言"可恢复原来的做法。
- 涉及文件：`js/ai-workflow.js`（按取值和任务选指令的纯函数，与任务指令放在一处）、`js/ai-optimize.js`（读取与保存设置、调用处）、`options.html`、三个语言文件、`tests/ai-workflow.test.cjs`、`CHANGELOG.md`。
- 验证：单元测试覆盖上表全部 15 格，以及缺省值和非法值按 `auto` 处理；设置页保存后重新打开仍是所选值。实际效果需要你在中文界面下用一篇英文文章各跑一次"整理"和"摘要"手动确认，自动测试不调用真实模型。

**A4　流式输出与取消**

- 现状：用 `$.ajax` 一次性请求，固定 90 秒超时，等待期间只有一行状态文字，不能取消。
- 做法（第一阶段）：改用 `fetch` 加各家的流式接口，文本边到边显示在审阅面板；加"停止"按钮（`AbortController`）；超时改为"一段时间没有新内容才算超时"。停止时保留已收到的部分，按截断结果处理。
- 做法（第二阶段，可选）：把请求移到 Service Worker，结果写入 `chrome.storage.local`，弹窗关闭后生成继续，重开即见结果。审阅面板本来就从存储恢复并监听变化，改动点集中在调用一侧。Service Worker 在长请求期间能否保持存活，需要用验收脚本实测。现有验收用例"关闭编辑器即释放任务"要相应改写。是否做见第 8 节。
- 涉及文件：`js/ai-optimize.js`（拆出的传输模块，见 S1）、`js/ai-review.js`、`popup.html`、`scripts/fixture-server.cjs`（模拟流式响应）。
- 验证：单元测试对四种流式格式各喂一段分块响应；验收脚本加"生成中点击停止，草稿不变、部分结果可见"。

**A5　错误信息**

- 做法：400、422 这类错误把服务商返回的 `error.message` 截取前 240 个字符附在提示后面（与 `showApiError` 对 Memos 的做法一致）。删除从未使用的 `LLM_CONFIG.defaults.temperature`。
- 涉及文件：`js/ai-optimize.js`、`js/llm-config.js`。

### 第 2 批（P1）：性能

**F1 + F2　标签与随机回顾**

- 现状：两者都调用 `MemosAPI.listMemos`，以每页 1000 条翻完全部笔记并下载全部正文。标签列表是"先拉取再切换显示"，所以点按钮收起列表时也会拉一遍。
- 做法：
  1. 一次全量扫描同时产出"标签集合"和"笔记资源名列表"，按账号缓存在 `chrome.storage.session`，有效期 10 分钟；过期后先用旧数据显示，后台刷新。
  2. 保存或归档成功后就地更新缓存。
  3. 随机回顾从缓存的资源名里挑一个，再用 `getMemo` 取单条。
  4. 标签列表已展开时再点按钮直接收起，不发请求；扫描期间显示加载状态。
  5. 落地前先对照真实的 26.11.1 实例确认有没有用户统计类接口能直接给出标签（旧版有 `users/{id}:getStats`）。有就优先用，全量扫描留作旧实例的回退。
- 涉及文件：`js/oper.js`、`js/memos-api.js`、新增一个小的缓存模块。
- 验证：单元测试——连续两次点击标签只产生一轮分页请求；保存带新标签的笔记后列表里立即出现该标签。

**F3　"加载更多"重复下载图片**

- 现状：每次加载更多都对全部结果调用 `renderMemoList`，它先撤销所有图片的对象地址，再重新请求每一张私有图片。
- 做法：加载更多只追加新一页的节点，并只为新节点取图；切换搜索条件或离开页面时才整体释放。
- 涉及文件：`js/oper.js`、`js/workspace.js`。
- 验证：单元测试——加载第二页后，第一页图片的请求次数仍为 1。

**F4 + F5　启动请求**

- 做法：空间列表和接口前缀按账号存入 `chrome.storage.local`。打开时先用缓存渲染，后台刷新，有变化再更新界面。保存前对空间的强校验（`Workspace.destination`）保持不变。
- 涉及文件：`js/workspace.js`、`js/memos-api.js`。
- 验证：`tests/memos-compat.test.cjs` 的"旧接口探测被缓存"用例扩展为跨页面实例；空间被移除后仍能在保存时被拦住。

### 第 3 批（P1）：健壮性

**R1　附件大小**

- 现状：粘贴、拖放、选择的文件不检查大小就写入 IndexedDB，保存时整体转成 base64 放进 JSON。超大文件会在保存时才失败，或者直接耗尽内存。
- 做法：暂存前检查大小，默认上限 30 MB，超出即提示并拒绝。若 26.11.1 能读到实例的上传上限就用实例值（需对照真实实例确认）。
- 涉及文件：`js/oper.js`、`js/staged-files.js`、语言文件。

**R2　剪藏图片上限**

- 现状：正文里有多少张图就抓多少张，四张一批，每张最长等 20 秒，单张不限大小。图多的页面可能拖到 Service Worker 被回收。
- 做法：每次剪藏最多抓 30 张、单张不超过 R1 的上限、总量不超过 60 MB；超出的保留为远程图片链接，并沿用现有的"部分图片无法读取"提示。数值是我的默认选择，可改。
- 涉及文件：`js/capture-service.js`、`js/staged-files.js`。
- 验证：单元测试——40 张图的页面只产生 30 次抓取，其余保留原链接且结果标记为部分成功。

**R3　无人绑定的附件**（P2）

- 现状（推断）：保存尝试 A 上传了附件但创建笔记失败；用户改了正文后再保存，签名变化产生尝试 B，附件重新上传。A 上传的那份留在服务器上不属于任何笔记。
- 做法：开始新尝试时，对上一尝试已上传且确认未绑定的附件发删除请求；失败不阻塞保存。落地前先写一个能复现的测试确认推断成立。
- 涉及文件：`js/staged-files.js`、`js/memos-api.js`、`js/oper.js`。

**R4 + R5　零散项**（P2）

- 服务器版本：打开弹窗时若距上次记录超过一天，后台刷新一次 `memosVersion`。
- 预览渲染：复用 S2 里共享的 Markdown 扫描器，跳过代码块。
- `window` 的 `unload` 事件改为 `pagehide`（`js/oper.js:179`）。

### 第 6 批（P2）：权限与凭据

**C1　站点权限**

- 现状：`host_permissions` 是全部 HTTP/HTTPS。目前有四处用到：访问用户填写的 Memos 实例、访问模型服务、在 Service Worker 里跨站抓取剪藏图片、从侧栏发起剪藏时注入脚本（侧栏里没有 `activeTab` 授权）。

**C2　凭据存放位置**

- 现状：Memos 令牌和全部模型密钥在 `chrome.storage.sync` 里，会随浏览器账号同步。`llmApiKey` 等五个旧键每次保存都再写一份，只为兼容回退到旧版本。
- 可选做法：设置页加"密钥仅保存在本机"，开启后迁到 `chrome.storage.local` 并清掉同步副本；停止写旧键。代价是换设备要重新填写。是否做见第 8 节。

**C3　右键菜单语言**

- 做法：Service Worker 监听 `userLanguage` 变化，读取对应语言文件后更新四个菜单项标题。
