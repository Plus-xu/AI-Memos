# 第 5 批 S4 第一步：用 fetch 替换 $.ajax Implementation Plan

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:subagent-driven-development (recommended) or superpowers:executing-plans to implement this plan task-by-task. Steps use checkbox (`- [ ]`) syntax for tracking.

**Goal:** 新增 `js/http.js`，把仅有的两处 `$.ajax`（Memos 接口、AI 接口）换成 `fetch`，行为不变。这是第 1 批 A4（流式输出与取消）的前置。

**Architecture:** 保持零构建。`Http.json` 是一层很薄的封装：发 JSON、收 JSON、带超时；失败时抛出的对象与调用方现在读取的 jqXHR 字段同形（`status`、`statusText`、`responseJSON`、`getResponseHeader`），所以 `showApiError`、`isMissingRoute`、`extractLLMErrorMessage` 一行不改。测试里对 `$.ajax` 的桩改为对 `fetch` 的桩，测试继续用"请求选项 → 回答"的方式描述服务器。

**Tech Stack:** 原生脚本、`fetch`、`AbortSignal.timeout`、`node --test`。

**Spec:** `docs/superpowers/specs/2026-11-20-optimization-roadmap-design.md`（第 7 节第 5 批 S4 的"第一步"。第二步的 DOM 替换不在本计划内）

## Global Constraints

- 不引入打包器、TypeScript、框架；新脚本写进 `popup.html`、`options.html`，排在 `js/memos-api.js` 和 `js/ai-optimize.js` 之前。Service Worker 不加载它（那里没有 `MemosAPI`）。
- 对外行为不变：同样的地址、方法、请求头（`Authorization`、各家的密钥头）、请求体；Memos 接口 30 秒超时，AI 接口 90 秒超时；不带 Cookie。
- 反目标照旧：不确定是否已写入的请求（超时、5xx、鉴权失败）绝不重放——"缺路由才换前缀重试"的逻辑不动。
- jQuery 本身不删（DOM 操作还在用）；`$.ajax` 在自有脚本里不再出现。
- `npm run check` 每个任务结束时通过。只做本地提交，不推送、不改版本号。
- 不覆盖 `artifacts/` 里已有的验收记录。

## 与 $.ajax 的对应关系（实现时逐条保持）

| 情形 | $.ajax（现状） | `Http.json` |
| --- | --- | --- |
| 2xx 且正文是 JSON | 以数据完成 | 以数据完成 |
| 204 | 以 `undefined` 完成 | 以 `undefined` 完成 |
| 2xx 但正文不是 JSON（旧实例回退到网页） | 失败，`status` 200，可读 `Content-Type` | 失败，`status` 200，`statusText: 'parsererror'`，`getResponseHeader` 可用 |
| 4xx / 5xx | 失败，`status`、`responseJSON`（正文是 JSON 时） | 相同 |
| 超时 | 失败，`status` 0，`statusText: 'timeout'` | 相同 |
| 网络错误 | 失败，`status` 0 | 失败，`status` 0，`statusText: 'error'` |

## Review Focus

1. 旧实例把未知接口路由回成网页（200 + `text/html`）：必须仍被识别为"缺路由"并换前缀重试，而不是当成成功。
2. 超时或网络中断发生在创建笔记时：只发一次请求，不换前缀重试，草稿保留。
3. 错误响应的正文不是 JSON（网关的 502 网页）：按状态码提示，不抛解析异常。
4. AI 服务返回 400 且带 `error.message`：提示里仍带上服务商给的原因。
5. 本地预览（`npm run preview`）不走真实网络：Memos 与 AI 请求仍由预览的模拟数据回答。
